# НарядAI — MVP

Интеллектуальная система выдачи и контроля рабочих нарядов (кейс АО «Костанайские минералы»).

| Часть | Стек | Где |
|---|---|---|
| Бэкенд | Python 3.13, FastAPI, SQLAlchemy 2 (async), PostgreSQL | `backend/` |
| Мобильное приложение (только исполнители) | Flutter 3.38, Riverpod 3, go_router, Dio | `mobile/` |
| Веб-панель (мастер, руководитель, администратор) | React 19, TypeScript, Vite, TanStack Query, React Router | `web/` |

## Быстрый старт — одним файлом

Нужен только [Docker](https://www.docker.com/products/docker-desktop/) (Compose 2.24+).

| ОС | Запуск |
|---|---|
| Windows | двойной клик по **`start.bat`** |
| Linux / macOS | `./start.sh` |

Скрипт проверит Docker (на Windows и macOS сам запустит Docker Desktop), подберёт свободные порты
(если 8080, 8000 или 5432 заняты — возьмёт следующие), соберёт контейнеры, дождётся готовности API,
загрузит демо-данные и откроет панель. В конце печатает адреса и демо-логины:

| Где | Логин | Пароль / ПИН |
|---|---|---|
| Веб-панель — администратор | `admin` | `Admin#2026` |
| Веб-панель — мастер | `master1` | `Master#2026` |
| Веб-панель — руководитель | `boss` | `Boss#2026` |
| Мобильное приложение — исполнители | `1001`–`1004` | ПИН `2580` |

Параметры: `-NoDemo` / `--no-demo` — без демо-данных (экран первичной настройки), `-Stop` / `--stop` — остановить
(данные сохраняются), `-NoOpen` / `--no-open` — не открывать браузер.

Без скрипта — то же вручную:

```bash
docker compose up -d --build
docker compose exec api python -m app.seed
```

- Веб-панель: **http://localhost:8080** — единственный порт, открытый в сеть (проксирует `/api`, `/ws`, `/media`)
- Swagger: http://localhost:8000/docs — API и PostgreSQL слушают только `127.0.0.1`

Работает «из коробки», без `.env`: при первом старте API генерирует уникальный ключ подписи
токенов (JWT) и сохраняет его в базе — он переживает перезапуски. Свои настройки (ключ JWT, Gemini, FCM)
можно задать в `backend/.env` по образцу `backend/.env.example`. Порты меняются без правки файлов:
`WEB_PORT=9080 API_PORT=9001 DB_PORT=55432 docker compose up -d`, пароль базы — `POSTGRES_PASSWORD`.

**Первый вход (настоящая установка).** Откройте панель — на пустой системе она сама покажет экран
«Добро пожаловать»: введите ФИО, логин и пароль администратора и при желании отметьте
«Заполнить справочники примерами». Консоль и правка файлов не нужны. Экран работает только пока
в системе нет ни одного администратора; дальше сотрудников регистрирует админ в разделе «Сотрудники».

**Демо-стенд.** Чтобы сразу получить тестовых пользователей и наряды:
`docker compose exec api python -m app.seed` — создаёт `admin`, `master1`, `boss`, исполнителей `1001`–`1004`
(пароли и ПИН в `app/seed.py`, только для демонстрации).

**Забыли пароль единственного администратора:**
`docker compose exec api python -m app.create_admin --login <логин>` — спросит новый пароль, вернёт роль
администратора и снимет блокировку (с `--fio` создаст нового).

Без Docker (локальная разработка; на Linux и macOS вместо `.venv/Scripts/` — `.venv/bin/`):

```bash
cd backend
python -m venv .venv && .venv/Scripts/pip install -r requirements-dev.txt
.venv/Scripts/python -m pytest          # тесты на SQLite, PostgreSQL не нужен
.venv/Scripts/uvicorn app.main:app --reload
```

### Мобильное приложение (Android)

**Готовый APK:** [`apk/naryad-ai.apk`](apk/naryad-ai.apk) — скачайте, скопируйте на телефон и установите
(Android попросит разрешить установку из этого источника). Подходит и для телефона, и для эмулятора.

Собрать APK из исходников самому (нужны Flutter 3.38 и Android SDK):

```powershell
cd mobile
.\build-android.ps1                                   # release-сборка: mobile\build\naryad-ai-release.apk
.\build-android.ps1 -Debug                            # debug-сборка: mobile\build\naryad-ai-debug.apk
.\build-android.ps1 -NoInstall                        # только собрать, не ставить на устройство
.\build-android.ps1 -ApiUrl http://192.168.1.50:8080  # необязательно: вшить другой адрес сервера по умолчанию
```

Если подключён эмулятор или телефон (USB-отладка), скрипт сразу ставит на него APK. Иначе скопируйте файл
на телефон и установите вручную.

**Один APK — и для эмулятора, и для телефона.** По умолчанию приложение ходит на `10.0.2.2:8000`
(так эмулятор видит компьютер, на котором запущен). На телефоне на экране входа нажмите **«Сервер → Изменить»**
и введите IP компьютера — его показывают `start.bat` / `start.sh` в конце запуска и панель в разделе
**«Настройки → Подключение мобильного приложения»**. Порт 8080 подставляется сам; адрес проверяется
и запоминается на телефоне. Телефон и компьютер должны быть в одной сети (телефон — в Wi-Fi того же роутера).

**Почему адресов несколько.** Показываются IP всех сетевых подключений компьютера с выходом в сеть.
Для телефона в обычном Wi-Fi нужен адрес домашней или офисной сети (обычно `192.168.0.x` или `192.168.1.x`).
Адреса виртуальных сетей (ZeroTier, VPN, Hyper-V) подходят, только если телефон подключён к той же виртуальной сети.

> Проект лежит в папке с кириллицей (`Костонай`), а Android Gradle Plugin и компилятор шейдеров
> Flutter (`impellerc`) с такими путями не работают. Скрипт копирует `mobile/` во временную папку
> с латинским путём (`%LOCALAPPDATA%\naryad-ai-build`), собирает APK там и кладёт результат в
> `mobile\build\naryad-ai-<режим>.apk`. Исходники правятся как обычно — в `Костонай`.
> `flutter test` и `flutter analyze` работают прямо в `mobile/`.

Веб-панель в режиме разработки (прокси на API `localhost:8000`):

```bash
cd web
npm install
npm run dev        # http://localhost:5173
```

## Веб-панель

| Раздел | Роли | Что умеет |
|---|---|---|
| Доска нарядов | мастер, руководитель, админ | счётчики смены; исполнители с цветом занятости и отметкой смены; канбан: выданные, принятые, в работе, в очереди, выполненные, просроченные; обновление по WebSocket |
| Выдача наряда | мастер, админ | одна форма «за минуту»: аварийный тип сам ставит критический приоритет, срок +2 ч и простой; исполнители отсортированы по занятости; быстрые сроки; до 5 фото «до»; Ctrl+Enter |
| Карточка наряда | все | детали, отчёт, материалы, ИИ-проверка с замечаниями и перепроверкой, фото, история; действия мастера: принять с оценкой, вернуть, переназначить, изменить, отменить |
| Все наряды | мастер, руководитель, админ | реестр с фильтрами и поиском, выгрузка в CSV для Excel |
| Аналитика | руководитель, мастер, админ | рейтинг исполнителей и простои оборудования за 7, 30 или 90 дней |
| Сотрудники | админ | регистрация, роли, бригады, сброс пароля и ПИН, блокировка |
| Справочники | админ | участки, оборудование, бригады, шифры неисправностей, материалы |
| Настройки | админ | ключ Gemini для ИИ-помощника и смысловой проверки; адреса сервера для подключения телефонов |
| ИИ-помощник | все | кнопка «✦ Помощник» внизу справа на любой странице |

Карточка открывается по параметру `?order=ID`, поэтому ссылку на наряд можно переслать. Исполнители входят только через мобильное приложение.

## Роли и права (RBAC)

Права проверяет бэкенд (зависимости `require_roles` + проверки в машине состояний). Мобильное приложение — только для исполнителей: «Мои наряды», карточка с действиями исполнителя (принять, в очередь, отклонить, начать, пауза, исполнено), закрытие наряда с фото и голосовым вводом, уведомления, ИИ-помощник. Мастер, руководитель и администратор при входе в приложение получают сообщение, что их рабочее место — веб-панель. Кнопки действий приложение берёт из `allowed_actions`, которые вычисляет сервер.

| Роль | Может |
|---|---|
| `master` | выдавать, редактировать, переназначать, отменять наряды; принимать работу с оценкой 1–5, возвращать на доработку; доска, счётчики, отметка смены исполнителей |
| `executor` | видит только свои наряды и невзятые наряды своей бригады; принять / в очередь / отклонить (с причиной) / начать / приостановить (с причиной) / исполнено; фото |
| `manager` | доска, счётчики, рейтинг, простои (только чтение) |
| `admin` | сотрудники (регистрация, роли, сброс пароля и ПИН, блокировка), справочники |

Вход по ПИН: 4–6 цифр. После 5 неверных попыток вход по ПИН блокируется на 5 минут. Access-токен живёт 12 ч (смена), refresh-токен — 14 дней.

## Жизненный цикл наряда

```
issued ──accept──► accepted ──start──► in_progress ──complete──► completed ──approve──► closed
  │  └──queue──► queued ──start──┘        │   ▲                      │
  │                                  pause│   │start            return (на доработку)
  └──reject (причина)──► rejected         ▼   │                      │
         ▲         └──reassign──► issued  paused ◄───────────────────┘ (в in_progress)
  cancel — мастер, из любого незакрытого статуса
```

- У исполнителя в работе одновременно один наряд. Начало **аварийного** наряда автоматически ставит текущий плановый на паузу; плановый в такой ситуации получает 409.
- Наряд на бригаду забирает первый исполнитель, который совершил над ним действие.
- «Просроченный» — производный признак (`is_overdue`), отдельная колонка канбана.
- Все переходы пишутся в `order_events` (аудит).

## ИИ-модули

| Модуль | Как работает |
|---|---|
| Контроль сроков | Фоновая задача каждые 60 с. Напоминание исполнителю за 30 мин до срока, уведомление исполнителю и мастерам при просрочке. **Прогноз риска:** медиана фактической длительности по этому оборудованию (или по участку и типу работ, или норматив). Если ожидаемое окончание позже срока, мастер получает предупреждение заранее. |
| Проверка выполнения | При «Исполнено»: полнота (≥ 5 слов, шифр, материалы при упоминании замены), соответствие отчёта проблеме (пересечение основ слов + категории неисправностей), согласованность шифра с текстом, логичность материалов (категория и типовой максимум из справочника), правдоподобность времени. Вердикт `ok` / `needs_review` / `rejected` и оценка 1–5 сохраняются в `ai_reports`. |
| LLM-проверка (опционально) | При заданном ключе Gemini в фоне запускается смысловая оценка (та же модель, что у помощника; ответ строго JSON по схеме). Её результат смешивается с оценкой по правилам. Любая ошибка LLM (сеть, лимит бесплатного тарифа) не мешает закрытию наряда. |
| Проверка фото | EXIF (камера, время съёмки, GPS), резкость, яркость, перцептивный хэш. Фото «после», идентичное «до» или снятое раньше выдачи наряда, снижает оценку. |
| Рейтинг | Баллы = 10 × сложность (приоритет, аварийность, критичность оборудования) × своевременность × качество (оценка мастера + ИИ). Штраф за отказы. `GET /api/v1/analytics/ratings`. |

## ИИ-помощник (чат) — Google Gemini, бесплатно

Кнопка **«✦ Помощник»** внизу справа — и в панели, и в мобильном приложении.
Отвечает на вопросы о нарядах, исполнителях, сменах, простоях, рейтинге и о том, как пользоваться системой
(«Что просрочено?», «Кто свободен?», «Как закрыть наряд?») — на языке интерфейса (русский или казахский).

- **Подключение без кода:** администратор → «Настройки» → вставить ключ Gemini → «Проверить и сохранить».
  Ключ бесплатный: [aistudio.google.com](https://aistudio.google.com) → **Get API key** → **Create API key**
  (карта не нужна). Ключ проверяется перед сохранением и дальше не показывается целиком. Тот же ключ включает
  смысловую ИИ-проверку отчётов. Альтернатива — `GEMINI_API_KEY` в `backend/.env`.
- **Бесплатный тариф:** ограничен числом запросов в минуту и в сутки — при превышении помощник просит подождать,
  а проверка наряда остаётся по правилам. На бесплатном тарифе Google может использовать запросы для улучшения
  своих сервисов; если это недопустимо, включите оплату для проекта ключа в AI Studio.
- **Только чтение:** у модели 7 функций (сводка смены, поиск нарядов, карточка наряда, исполнители,
  рейтинг, простои, справочники). Создавать или менять она ничего не может.
- **Права:** функции работают от имени пользователя — исполнитель видит только свои наряды,
  аналитика доступна мастеру, руководителю и администратору.
- **Модель:** `gemini-3.5-flash` (меняется переменной `LLM_MODEL`). Если модель перегружена или недоступна,
  запрос автоматически повторяется на запасных: `gemini-3.5-flash-lite`, затем `gemini-3.7-flash`
  (список — `LLM_FALLBACK_MODELS`).
  Запросы идут напрямую в REST API Gemini через httpx (без SDK), ответ стримится (SSE).

## Языки: русский и казахский

Переключатель **«Қаз / Рус»** — в шапке панели и на экранах входа; в шапке приложения — значок языка (меню «Қазақша / Русский»). Выбор запоминается на устройстве.
Интерфейс переводится полностью; сервер отдаёт свои тексты (ошибки, уведомления, журнал наряда, ИИ-проверку)
на языке из заголовка `Accept-Language`. Текст, который пишут люди (описания, отчёты, причины), не переводится.
Словари: `web/src/i18n/kk.ts`, `mobile/lib/core/i18n/kk.dart`, `backend/app/core/i18n_kk.py`; тесты падают,
если в коде появилась строка без казахского перевода.

## Что сделать перед продом

- **Alembic-миграции** вместо `create_all` (`AUTO_CREATE_TABLES=false`).
- **Фото** сейчас раздаются статикой `/media` без авторизации (имена файлов — случайные UUID). Нужно перенести в S3/MinIO с подписанными ссылками.
- **WebSocket** работает в памяти одного процесса. Для нескольких воркеров нужен Redis pub/sub. Токен передаётся в query и попадает в access-лог uvicorn: отключите лог query или передавайте токен первым сообщением.
- **Push в фоне:** подключить `firebase_messaging` в приложении (нужен `google-services.json`) и `FCM_CREDENTIALS_FILE` на сервере. Бэкенд уже отправляет push.
- Rate limiting на `/auth/*` на уровне reverse proxy.
