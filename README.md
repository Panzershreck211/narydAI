# НарядAI — MVP

Интеллектуальная система выдачи и контроля рабочих нарядов (кейс АО «Костанайские минералы»).

| Часть | Стек | Где |
|---|---|---|
| Бэкенд | Python 3.13, FastAPI, SQLAlchemy 2 (async), PostgreSQL | `backend/` |
| Мобильное приложение | Flutter 3.38, Riverpod 3, go_router, Dio | `mobile/` |
| Веб-панель (мастер, руководитель, администратор) | React 19, TypeScript, Vite, TanStack Query, React Router | `web/` |

## Быстрый старт

```bash
cp backend/.env.example backend/.env      # поменяйте JWT_SECRET
docker compose up -d --build
```

- Веб-панель: **http://localhost:8080**
- Swagger: http://localhost:8000/docs

**Первый вход (настоящая установка).** Откройте панель — на пустой системе она сама покажет экран
«Добро пожаловать»: введите ФИО, логин и пароль администратора и при желании отметьте
«Заполнить справочники примерами». Консоль и правка файлов не нужны. Экран работает только пока
в системе нет ни одного администратора; дальше сотрудников регистрирует админ в разделе «Сотрудники».

**Демо-стенд.** Чтобы сразу получить тестовых пользователей и наряды:
`docker compose exec api python -m app.seed` — создаёт `admin`, `master1`, `boss`, исполнителей `1001`–`1004`
(пароли и ПИН в `app/seed.py`, только для демонстрации).

**Забыли пароль единственного администратора:**
`docker compose exec api python -m app.create_admin --login <логин>` — спросит новый пароль, вернёт роль
администратора и снимет блокировку (с `--fio` создаст нового).

Без Docker (локальная разработка):

```bash
cd backend
python -m venv .venv && .venv/Scripts/pip install -r requirements-dev.txt
.venv/Scripts/python -m pytest          # тесты на SQLite, PostgreSQL не нужен
.venv/Scripts/uvicorn app.main:app --reload
```

Мобильное приложение (Android) — собрать и поставить на эмулятор или телефон:

```powershell
cd mobile
.\build-android.ps1                                   # release для эмулятора (API 10.0.2.2:8000)
.\build-android.ps1 -ApiUrl http://192.168.1.50:8000  # для телефона в той же Wi-Fi сети
.\build-android.ps1 -Debug                            # debug-сборка
```

> Проект лежит в папке с кириллицей (`Костонай`), а Android Gradle Plugin и компилятор шейдеров
> Flutter (`impellerc`) с такими путями не работают. Скрипт копирует `mobile/` во временную папку
> с латинским путём (`%LOCALAPPDATA%\naryad-ai-build`), собирает APK там и кладёт результат в
> `mobile\build\naryad-ai-<режим>.apk`. Исходники правятся как обычно — в `Костонай`.
> `flutter test` и `flutter analyze` работают прямо в `mobile/`.

Веб-панель в режиме разработки (прокси на API `localhost:8000`):

```bash
cd web
npm install
npm run dev        # http://localhost:5173
```

## Веб-панель

| Раздел | Роли | Что умеет |
|---|---|---|
| Доска нарядов | мастер, руководитель, админ | счётчики смены; исполнители с цветом занятости и отметкой смены; канбан: выданные, принятые, в работе, в очереди, выполненные, просроченные; обновление по WebSocket |
| Выдача наряда | мастер, админ | одна форма «за минуту»: аварийный тип сам ставит критический приоритет, срок +2 ч и простой; исполнители отсортированы по занятости; быстрые сроки; до 5 фото «до»; Ctrl+Enter |
| Карточка наряда | все | детали, отчёт, материалы, ИИ-проверка с замечаниями и перепроверкой, фото, история; действия мастера: принять с оценкой, вернуть, переназначить, изменить, отменить |
| Все наряды | мастер, руководитель, админ | реестр с фильтрами и поиском, выгрузка в CSV для Excel |
| Аналитика | руководитель, мастер, админ | рейтинг исполнителей и простои оборудования за 7, 30 или 90 дней |
| Сотрудники | админ | регистрация, роли, бригады, сброс пароля и ПИН, блокировка |
| Справочники | админ | участки, оборудование, бригады, шифры неисправностей, материалы |

Карточка открывается по параметру `?order=ID`, поэтому ссылку на наряд можно переслать. Исполнители входят только через мобильное приложение.

## Роли и права (RBAC)

Права проверяет бэкенд (зависимости `require_roles` + проверки в машине состояний). Мобильное приложение дублирует их в роутере и показывает только кнопки из `allowed_actions`, которые вычисляет сервер.

| Роль | Может |
|---|---|
| `master` | выдавать, редактировать, переназначать, отменять наряды; принимать работу с оценкой 1–5, возвращать на доработку; доска, счётчики, отметка смены исполнителей |
| `executor` | видит только свои наряды и невзятые наряды своей бригады; принять / в очередь / отклонить (с причиной) / начать / приостановить (с причиной) / исполнено; фото |
| `manager` | доска, счётчики, рейтинг, простои (только чтение) |
| `admin` | сотрудники (регистрация, роли, сброс пароля и ПИН, блокировка), справочники |

Вход по ПИН: 4–6 цифр. После 5 неверных попыток вход по ПИН блокируется на 5 минут. Access-токен живёт 12 ч (смена), refresh-токен — 14 дней.

## Жизненный цикл наряда

```
issued ──accept──► accepted ──start──► in_progress ──complete──► completed ──approve──► closed
  │  └──queue──► queued ──start──┘        │   ▲                      │
  │                                  pause│   │start            return (на доработку)
  └──reject (причина)──► rejected         ▼   │                      │
         ▲         └──reassign──► issued  paused ◄───────────────────┘ (в in_progress)
  cancel — мастер, из любого незакрытого статуса
```

- У исполнителя в работе одновременно один наряд. Начало **аварийного** наряда автоматически ставит текущий плановый на паузу; плановый в такой ситуации получает 409.
- Наряд на бригаду забирает первый исполнитель, который совершил над ним действие.
- «Просроченный» — производный признак (`is_overdue`), отдельная колонка канбана.
- Все переходы пишутся в `order_events` (аудит).

## ИИ-модули

| Модуль | Как работает |
|---|---|
| Контроль сроков | Фоновая задача каждые 60 с. Напоминание исполнителю за 30 мин до срока, уведомление исполнителю и мастерам при просрочке. **Прогноз риска:** медиана фактической длительности по этому оборудованию (или по участку и типу работ, или норматив). Если ожидаемое окончание позже срока, мастер получает предупреждение заранее. |
| Проверка выполнения | При «Исполнено»: полнота (≥ 5 слов, шифр, материалы при упоминании замены), соответствие отчёта проблеме (пересечение основ слов + категории неисправностей), согласованность шифра с текстом, логичность материалов (категория и типовой максимум из справочника), правдоподобность времени. Вердикт `ok` / `needs_review` / `rejected` и оценка 1–5 сохраняются в `ai_reports`. |
| LLM-проверка (опционально) | При заданном `ANTHROPIC_API_KEY` в фоне запускается смысловая оценка через Claude (`claude-opus-5-5`, structured output). Её результат смешивается с оценкой по правилам. Включён серверный fallback модели при отказе. Любая ошибка LLM не мешает закрытию наряда. |
| Проверка фото | EXIF (камера, время съёмки, GPS), резкость, яркость, перцептивный хэш. Фото «после», идентичное «до» или снятое раньше выдачи наряда, снижает оценку. |
| Рейтинг | Баллы = 10 × сложность (приоритет, аварийность, критичность оборудования) × своевременность × качество (оценка мастера + ИИ). Штраф за отказы. `GET /api/v1/analytics/ratings`. |

## ИИ-помощник (чат)

Кнопка **«✦ Помощник»** внизу справа на любой странице панели. Отвечает по-русски на вопросы о нарядах,
исполнителях, сменах, простоях, рейтинге и о том, как пользоваться системой («Что просрочено?»,
«Кто свободен?», «Как зарегистрировать сотрудника?»). Номера нарядов в ответе кликабельны.

- **Подключение без кода:** администратор → «Настройки» → вставить ключ Claude (console.anthropic.com →
  API Keys) → «Проверить и сохранить». Ключ проверяется перед сохранением и дальше не показывается целиком.
  Тот же ключ включает смысловую ИИ-проверку отчётов. Альтернатива — `ANTHROPIC_API_KEY` в `backend/.env`.
- **Только чтение:** у модели 7 инструментов (сводка смены, поиск нарядов, карточка наряда, исполнители,
  рейтинг, простои, справочники). Создавать или менять она ничего не может.
- **Права:** инструменты работают от имени пользователя — исполнитель видит только свои наряды,
  аналитика доступна мастеру, руководителю и администратору.
- **Модель:** `claude-opus-5-5` (`LLM_MODEL`), низкое усилие для быстрых ответов, серверный fallback
  при отказе модели, ответ стримится (SSE) — текст появляется по мере генерации.

## Что сделать перед продом

- **Alembic-миграции** вместо `create_all` (`AUTO_CREATE_TABLES=false`).
- **Фото** сейчас раздаются статикой `/media` без авторизации (имена файлов — случайные UUID). Нужно перенести в S3/MinIO с подписанными ссылками.
- **WebSocket** работает в памяти одного процесса. Для нескольких воркеров нужен Redis pub/sub. Токен передаётся в query и попадает в access-лог uvicorn: отключите лог query или передавайте токен первым сообщением.
- **Push в фоне:** подключить `firebase_messaging` в приложении (нужен `google-services.json`) и `FCM_CREDENTIALS_FILE` на сервере. Бэкенд уже отправляет push.
- Rate limiting на `/auth/*` на уровне reverse proxy.
